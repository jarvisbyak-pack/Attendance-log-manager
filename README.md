# Attendance Log Manager

A mobile-friendly reception frontend with a Google Apps Script API and Google Sheets as the source of truth.

## Architecture
- GitHub Pages (or another static host): `index.html`, `styles.css`, `config.js`, `app.js`.
- Google Apps Script: `Code.gs`, `Config.gs`, `Sheets.gs`, `Members.gs`, `Attendance.gs`, `Notifications.gs`, `Admin.gs`, `Utils.gs`.
- Google Sheets tabs: `Clients`, `Membership`, `Attendance`.
- Telegram notifications are sent server-side only; the bot token and chat ID must never be placed in frontend settings.

## Frontend files
1. `index.html` — reception, live attendance, history, members, expiry monitor, admin/settings dialogs.
2. `styles.css` — responsive dark UI and status colors.
3. `app.js` — UI interactions and API calls.
4. `config.js` — public defaults only; the backend URL is configured by an admin at runtime.

## Apps Script files
Create an Apps Script project bound to the correct spreadsheet or use a standalone project. Add the `.gs` files and `appsscript.json`. Configure Script Properties before deployment:

- `SPREADSHEET_ID`: ID from the Google Sheets URL.
- `ADMIN_PIN_HASH`: SHA-256 hash generated by the `setInitialAdminPinHash(pin)` helper. Run this helper manually from the Apps Script editor with a temporary PIN argument; never commit the PIN.
- `EXPIRY_WARNING_DAYS`: `5` by default.
- `TELEGRAM_ENABLED`: `true` or `false`.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`: only if Telegram is enabled.
- `NOTIFY_ENTRY`, `NOTIFY_EXIT`, `NOTIFY_EXPIRY`, `NOTIFY_SECURITY`: `true` or `false`.

Deploy as a Web App executing as the deploying account. The endpoint is anonymous at the transport layer so the static frontend can call it; all non-health API actions require the admin session token. Restrict spreadsheet access and review deployment policy before production use.

## API actions
`health` (public), `admin.authenticate` (public PIN verification), and authenticated actions `members.search`, `members.expiry`, `attendance.entry`, `attendance.exit`, `attendance.live`, `attendance.history`, `attendance.snapshot`, `admin.notificationSettings`.

## Attendance behavior
- Duplicate open entries are blocked.
- Exit without a same-day open entry is blocked and audited.
- Attendance writes are guarded by a script lock.
- Membership status is calculated server-side: `ACTIVE`, `EXPIRING SOON`, `EXPIRED`.
- Expiry warning defaults to five days.
- **Expired-member access policy is intentionally unresolved**: current code flags an expired member but still permits an entry. Confirm the policy before production.
- UI does not poll automatically; refresh/search/actions make requests.

## Important current limitations to resolve before production
1. The admin session currently protects all API actions except `health` and `admin.authenticate`, including ordinary reception lookup/actions. If the intended operational model is a public reception screen with only Settings protected by PIN, split the API authorization model before production. Do not weaken it without approval.
2. The `Membership` tab's handling of multiple historical membership rows is not yet defined; the current lookup selects the first matching row.
3. CORS behavior and redirects must be verified against the deployed Apps Script URL and chosen static host.
4. The Apps Script source cannot be fully tested outside Google Apps Script because it relies on `SpreadsheetApp`, `PropertiesService`, `CacheService`, `LockService`, and `UrlFetchApp`.
5. Production verification requires a test spreadsheet and a deployed Apps Script Web App. Do not use real member data until the test checklist passes.

## Local validation
- `node --check app.js`
- `node --check config.js`
- Parse `appsscript.json` as JSON.
- Serve the folder through a local HTTP server and confirm all static assets return HTTP 200.
- Run Apps Script tests in a non-production spreadsheet for header variants, date handling, duplicate entry, exit without entry, lock contention, and Telegram disabled/enabled paths.
